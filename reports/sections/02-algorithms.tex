\section{Data Structure / Algorithm Specification}
\label{sec:algorithms}
\subsection{CSR Graph and Shared Interface}
Vertices are numbered $1,\ldots,n$. The CSR representation stores a contiguous
edge array and an offset array of length $n+1$, grouping arcs by their source.
Visiting the outgoing arcs of a vertex therefore takes time proportional to its
out-degree. Each edge stores a destination and an integer weight, and shortest
distances use signed 64-bit integers. The initial infinity value is set to one
quarter of the maximum value of this type, which leaves headroom for distance
addition over the inputs used here. The implementation does not provide general
overflow detection for arbitrarily large inputs.

The priority-queue interface provides \code{push_or_decrease(key,v)}, \code{pop()},
\code{empty()}, and \code{clear()}. Implementations that support decrease-key use
the vertex index to locate an entry, while a shared base class uses timestamps to
identify the current in-heap entry. \code{pop()} clears the corresponding in-heap
marker. The queue must be empty at the end of a complete search and can then be reused.

\subsection{Main Dijkstra Loop}
The source distance is initialized to zero, and each relaxation updates a label
using the length of an already discovered path. The standard-library version may
contain stale keys, so the main loop skips outdated entries.

\begin{lstlisting}[caption={Shared Dijkstra pseudocode}]
DIJKSTRA(G, s, Q):
  fill d[0..n] with INF
  d[s] = 0; Q.push_or_decrease(0, s)
  while not Q.empty():
    (key, u) = Q.pop()
    if key > d[u]: continue
    for each (v, w) in G[u]:
      if d[u] + w < d[v]:
        d[v] = d[u] + w
        Q.push_or_decrease(d[v], v)
  return d
\end{lstlisting}

\subsection{Binary Heap, Segment Tree, and PBDS}
\textbf{Standard-library priority queue.} The minimum heap stores $(d,v)$ pairs.
Each distance improvement inserts a new entry, and outdated entries are discarded
when removed. The heap may therefore contain multiple keys for the same vertex,
and its space usage grows with the number of successful relaxations.

\textbf{Custom binary heap.} The array \code{heap[pos]} stores vertices,
\code{idx[v]} stores positions, and \code{key[v]} stores the current keys. Insertion
places a vertex at the end and sifts it upward; decrease-key starts from
\code{idx[v]} and also sifts upward. Extract-min moves the last vertex to the root
and sifts it downward, with every swap updating the positions of both vertices.
Each vertex has at most one entry in the heap.

\textbf{Segment-tree heap.} Each vertex corresponds to a leaf, and each internal
node stores the minimum key in its interval and the associated vertex. Insertion
and decrease-key update the path to the root. Extract-min reads the vertex stored
at the root and sets its leaf to $\infty$. Even when the minimum key itself does not
change, propagation must continue if the minimizing vertex changes, preventing
stale vertices with equal keys. The largest vertex index and the sentinel leaf are
kept separate.

\textbf{PBDS pairing and thin heaps.} The adaptor stores a \code{point_iterator}
for each vertex. The first insertion calls \code{push}, and later updates use
\code{modify}. Internal heap-order maintenance is delegated to the GNU library.
This project does not reimplement either library heap and does not equate their
decrease-key amortized bounds with that of a Fibonacci heap.

\subsection{Fibonacci Heap}
Each vertex has a slot in a preallocated node array. A node stores its key, parent,
children, left and right sibling pointers, degree, and mark. Both the root list and
the child lists are circular doubly linked lists, with a separate pointer to the
minimum root. Insertion splices a singleton tree into the root list. Extract-min
promotes the children of the minimum root and then links trees of equal degree.
The root list is processed by unlinking the current root, which avoids relying on a
circular termination point that can become invalid while consolidation is in progress.

\begin{lstlisting}[caption={Key operations of the Fibonacci heap}]
INSERT(v, key):
  initialize node[v] as a singleton unmarked root
  splice node[v] into root list; update minimum
EXTRACT_MIN():
  remove minimum root z
  promote all children of z to unmarked roots
  while two roots have the same degree:
    link the larger-key root under the smaller-key root
  rebuild root list and minimum; return z
DECREASE(v, key):
  node[v].key = key
  if v violates heap order with its parent:
    cut v to the root list
    mark its parent on the first child loss
    repeatedly cut marked ancestors after another child loss
  update minimum if needed
\end{lstlisting}

A mark records whether a non-root node has already lost one child. A potential
function may be chosen as $\Phi=t+2q$, where $t$ is the number of roots and $q$ is
the number of marked nodes. The reduction in marks caused by cascading cuts pays
for the cut operations. The Fibonacci heap therefore supports amortized $O(1)$
insertion and decrease-key, amortized $O(\log n)$ extract-min, and the
$O(m+n\log n)$ bound for Dijkstra's algorithm \cite{fredman}. This bound describes
the total sequence of operations; it does not imply that every extract-min takes
logarithmic time.

\subsection{Monotonic Radix Heap}
The radix heap stores the most recently extracted key $L$. A key $k$ is placed in
the bucket numbered $b(k)=\operatorname{bitwidth}(k\mathbin{\mathrm{xor}}L)$; bucket
zero contains only keys equal to $L$. If bucket zero is empty, the smallest key in
the lowest nonempty bucket becomes the new $L$, and that bucket is redistributed
according to the new $L$. Redistribution reduces the bucket indices.
Decrease-key uses a handle that records the bucket index and the entry's position
within the bucket. A cross-bucket move swaps entries and repairs the handle of the
swapped entry.

\begin{lstlisting}[caption={Extract-min in the radix heap}]
POP():
  if bucket[0] is empty:
    b = smallest nonempty bucket id
    L = minimum key in bucket[b]
    redistribute every entry in bucket[b] using bitwidth(key XOR L)
  remove and return an entry from bucket[0]
  if all buckets are empty: reset L = 0 for the next query
\end{lstlisting}

A valid insertion requires $k\ge L$; it does not require all inserted keys to be
globally increasing. Nonnegative edge weights in Dijkstra's algorithm ensure that a
newly discovered candidate distance is no smaller than the most recently extracted
valid distance, which satisfies this condition. The current implementation has 32
buckets and uses 25 bits for the position information in each handle. It is not a
general radix heap for arbitrary 64-bit key ranges.

\subsection{Two Label-Correcting Algorithms}
\textbf{FIFO SPFA.} The queue stores $(d,v)$ entries, and each successful
relaxation inserts a new entry. Outdated distances are skipped when an entry is
removed. There is no separate in-queue marker, so duplicate entries are possible;
memory use and operation counts therefore should not be analyzed as if each vertex
had exactly one queue entry.

\textbf{SLF+LLL SPFA.} The deque stores vertices and maintains an in-queue marker.
When a successful relaxation improves a vertex that is not queued, the vertex is
pushed to the front if its label is smaller than the current front label (SLF);
otherwise it is pushed to the back. Before processing the front vertex, the
algorithm moves it to the back if its label is greater than the average label of
queued vertices (LLL). The average is maintained from the sum of queued labels and
updated when an already queued label decreases. These heuristics change only the
relaxation order and provide no Dijkstra-style finalization guarantee.

\begin{lstlisting}[caption={Queue scheduling rules for SLF+LLL},float=t]
ENQUEUE(v):
  if queue empty or d[v] < d[front]: push_front(v)
  else: push_back(v)
  in_queue[v] = true; sum += d[v]; count += 1
PROCESS():
  while d[front] * count > sum: rotate front to back
  u = pop_front(); in_queue[u] = false
  sum -= d[u]; count -= 1
  relax outgoing arcs of u
  update sum on an already queued label decrease
  otherwise enqueue each newly improved vertex
\end{lstlisting}
