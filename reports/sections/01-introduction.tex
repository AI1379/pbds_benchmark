\section{Introduction}
\label{sec:intro}
\subsection{Problem Description and Objectives}
Given a directed graph $G=(V,E)$, nonnegative edge weights
$w:E\to\mathbb{Z}_{\ge0}$, and a source vertex $s$, the single-source shortest-path
problem asks for the shortest distance $d[v]$ from $s$ to every vertex. The distance
to an unreachable vertex is denoted by $\infty$. Let $n=|V|$ and $m=|E|$; throughout
this report, $m$ refers to the number of directed arcs.

Dijkstra's greedy order depends on a minimum-priority queue. Binary heaps, segment
trees, and Fibonacci heaps handle insertion, decrease-key, and extract-min
differently, which leads to different asymptotic costs and implementation constants.
When distances are nonnegative integers, a monotonic radix heap is another option.

The study addresses two questions: whether the lower theoretical cost of
decrease-key operations translates into faster searches, and how the speed ordering
of the implementations changes with graph structure.

\subsection{Implementations and Experimental Scope}
We implemented and compared seven queues for Dijkstra's algorithm: the standard
library priority queue, a custom binary heap, a segment-tree heap, a Fibonacci heap,
a radix heap, the GNU PBDS pairing heap, and the GNU PBDS thin heap. Except for the
standard-library version, which simulates decrease-key by inserting duplicate
entries, the implementations support locating a vertex and updating its key.
FIFO SPFA and SLF+LLL SPFA are queue-based label-correcting algorithms rather than
heap variants of Dijkstra's algorithm, and they are treated separately in this report.

All implementations share the main loop in \code{general-dijkstra.hpp} and the same
CSR graph representation. Random-graph and fixed-density experiments use seed 42
and the same graph-generation rule for each parameter set. The road-network
experiments use \code{USA-road-d.NY} and \code{USA-road-d.BAY}, with 1,000 generated
random source-target queries and seed 971.

\subsection{Experimental Setup}
Although the road-network input is expressed as point-to-point queries, the current
algorithms compute the complete distance array from each source and drain the queue.
The target vertex does not trigger early termination. Consequently, the reported
``ms/query'' is \textbf{the mean time for a complete single-source search triggered
by one source-target pair}; it is not the latency of a point-to-point search that
stops at the target. This study does not include path recovery, preprocessing
indices, or parallel search.

Random-graph and fixed-density experiments are repeated three times for each
configuration. Each road-network implementation runs one complete batch containing
1,000 queries.
